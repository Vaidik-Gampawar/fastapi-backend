# 16. READ Operation with Database

## What this code does
Adds the "R" of CRUD on top of lecture 15 — fetching **all** todos and fetching **one specific** todo, both via SQLAlchemy queries instead of looping through a Python list (like the old lecture 6 version did).

```python
# Read All Data
@app.get("/todos")
def get_todos(db: Session = Depends(get_db)):
    todo = db.query(Todo).all()
    return {"Total": len(todo), "data": todo}

@app.get("/todos/{todo_id}")
def get_todo(todo_id: int, db: Session = Depends(get_db)):
    todo = db.query(Todo).filter(Todo.id == todo_id).first()
    if not todo:
        raise HTTPException(status_code=404, detail="Todo Not Found")
    return {"message": "Todo Found", "data": todo}
```
*(setup above these routes is unchanged from lectures 14–15)*

## Key concepts

**1. `db.query(Todo)` — starting a query**
```python
db.query(Todo)
```
This tells SQLAlchemy "I want to query the `todos` table" — using the Python class `Todo`, not a raw SQL string. This is the core benefit of an ORM: your queries are built with Python method chaining instead of writing `"SELECT * FROM todos"` by hand.

**2. `.all()` — get every row**
```python
todo = db.query(Todo).all()
```
Executes the query and returns **every row** in the table as a list of `Todo` objects. This is the ORM equivalent of `SELECT * FROM todos`.

**3. `.filter(...)` — narrowing results**
```python
db.query(Todo).filter(Todo.id == todo_id)
```
This is the ORM equivalent of a SQL `WHERE` clause. `Todo.id == todo_id` looks like a normal Python comparison, but SQLAlchemy actually turns it into `WHERE id = <todo_id>` in the generated SQL — it doesn't literally evaluate to `True`/`False` here; it builds a filter condition object instead.

**4. `.first()` vs `.all()`**
```python
db.query(Todo).filter(Todo.id == todo_id).first()
```
- `.all()` → returns a list (could be empty, could have many items)
- `.first()` → returns just the **first matching row** (or `None` if nothing matches) — perfect for "get me the one todo with this id," since `id` should be unique anyway

**5. Handling "not found" — familiar pattern**
```python
if not todo:
    raise HTTPException(status_code=404, detail="Todo Not Found")
```
Since `.first()` returns `None` when nothing matches, `if not todo:` catches that case. This is the same `HTTPException` pattern from lecture 9 — now applied to a real database lookup instead of a hardcoded check.

**6. Comparing this to the old in-memory version (lecture 6)**
| | In-memory list (lecture 6) | Database (this lecture) |
|---|---|---|
| Get all | `return todos` | `db.query(Todo).all()` |
| Get one | manual `for` loop + `if` | `.filter(...).first()` |
| Not found | `return {"error": ...}` (bad — still `200`) | `raise HTTPException(404, ...)` (correct) |
| Persistence | lost on restart | saved permanently in `test.db` |

The querying logic is genuinely simpler and more powerful with SQLAlchemy — no manual looping needed, and the database engine handles the actual searching efficiently (especially with `index=True` on `id`, set back in lecture 14).

## Quick recap
- `db.query(Model)` → starts a query against that table
- `.all()` → get every matching row, as a list
- `.filter(condition)` → equivalent to SQL `WHERE`, narrows down results
- `.first()` → get just the first match, or `None` if nothing matches
- `if not result: raise HTTPException(404, ...)` → standard "not found" handling for database lookups
