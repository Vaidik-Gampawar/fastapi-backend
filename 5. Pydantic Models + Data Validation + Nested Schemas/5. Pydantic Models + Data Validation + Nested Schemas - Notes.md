# 5. Pydantic Models + Data Validation + Nested Schemas

## What this code does
Builds on lecture 4 by showing you can **nest one Pydantic model inside another** — useful when your data naturally has sub-structure (like a user having an address).

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Address(BaseModel):
    city: str
    pincode: int

class User(BaseModel):
    name: str
    age: int
    address: Address

@app.post("/create_user")
def create_user(user: User):
    return {
        "message": "User Created",
        "user": user
    }
```

## Key concepts

**1. The simple version (commented out)**
The commented-out code at the top is the "flat" version from before — a `User` with just `name`, `age`, `email` as plain fields. Keeping it commented is a nice way to compare "before vs after."

**2. Nested models**
```python
class Address(BaseModel):
    city: str
    pincode: int

class User(BaseModel):
    name: str
    age: int
    address: Address
```
`Address` is a normal Pydantic model on its own. Then `User` uses `Address` **as a type** for its `address` field. This mirrors how real-world JSON is often structured — objects inside objects.

**3. What the expected request body looks like now**
```json
{
  "name": "Vaidik",
  "age": 22,
  "address": {
    "city": "Pune",
    "pincode": 411001
  }
}
```
The `address` field must itself be a JSON object matching the `Address` shape — not a flat string.

**4. Validation goes deep, automatically**
FastAPI/Pydantic doesn't just check that `address` exists — it validates **inside** it too:
- `address.city` must be a string
- `address.pincode` must be an integer
- If `address` is missing entirely, or `pincode` is sent as `"abc"`, you still get an automatic `422` error, with details pointing to exactly which nested field failed.

**5. Why this matters**
As your APIs grow, data rarely stays flat. Nesting models keeps things:
- **Organized** — `Address` can be reused in other models (e.g., a `Shop` or `Order` might also need an address)
- **Readable** — the structure of your model mirrors the structure of your real-world data
- **Still fully validated** — no extra work needed, nesting doesn't weaken validation

## Quick recap
- A Pydantic model can be used as the **type of a field** in another model → this creates a nested schema
- Request JSON must match the nested structure exactly (object inside object)
- Validation applies recursively — errors in nested fields are still caught automatically
- Nesting = better organization and reusability as your data models grow
