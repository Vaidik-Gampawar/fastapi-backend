# 3. Query Parameter + Optional + Default Values

## What this code does
Introduces **query parameters** — the `?key=value` part of a URL — and shows how to make them optional or give them defaults.

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/users")
def get_user(name: str = None):
    return {"Name": name}

@app.get("/products")
def get_products(limit: int = 10):
    return {"Limit": limit}

@app.get("/items")
def get_item(name: str = None, price: int = 0):
    return {
        "name": name,
        "price": price
    }
```

## Key concepts

**1. Query parameters vs path parameters**
- Path parameter (lecture 2): part of the URL path itself → `/users/42`
- Query parameter (this lecture): comes after a `?` → `/users?name=vaidik`

**2. How FastAPI decides "path param" vs "query param"**
FastAPI figures this out automatically based on the function signature:
- If a parameter name appears in `{}` in the route path → it's a **path parameter**
- If it does NOT appear in the path but IS a function argument → it's a **query parameter**

That's why `name` and `price` aren't in `"/users"` or `"/items"` in the decorator, but they're still recognized as valid inputs.

**3. Optional parameters — `= None`**
```python
def get_user(name: str = None):
```
Giving a parameter a default value of `None` makes it **optional**. If the request doesn't include `?name=...`, it just falls back to `None` instead of throwing an error.
- `/users` → `name = None`
- `/users?name=vaidik` → `name = "vaidik"`

**4. Default values (not just optional)**
```python
def get_products(limit: int = 10):
```
Same idea, but with a meaningful default instead of `None`.
- `/products` → `limit = 10` (default used)
- `/products?limit=5` → `limit = 5` (overridden)

**5. Multiple query parameters**
```python
def get_item(name: str = None, price: int = 0):
```
You can combine as many query parameters as you want — just add more function arguments. FastAPI matches them by name.
- `/items?name=Pen&price=20` → `{"name": "Pen", "price": 20}`
- `/items` → `{"name": None, "price": 0}` (both fall back to defaults)

**6. Type validation still applies**
`price: int = 0` means FastAPI will still validate that price is a valid integer if provided — same automatic validation as with path parameters.

## Quick recap
- Query params = extra data passed via `?key=value` in the URL, not part of the path
- A function argument becomes a query param automatically if it's *not* in `{}` in the route
- `= None` → makes the parameter optional
- `= <some value>` → sets a default that's used when the param is omitted
- Multiple query params are just multiple function arguments, in any order in the URL
