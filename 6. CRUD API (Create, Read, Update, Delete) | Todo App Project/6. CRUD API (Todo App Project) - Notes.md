# 6. CRUD API (Create, Read, Update, Delete) | Todo App Project

## What this code does
Brings everything from lectures 1–5 together into a real mini-project: a **Todo app** with all four CRUD operations, backed by a simple in-memory Python list.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

todos = []

class Todo(BaseModel):
    id: int
    title: str
    completed: bool

@app.post("/todos")
def create_todo(todo: Todo):
    todos.append(todo)
    return {"message": "Todo Created", "data": todo}

@app.get("/todos")
def get_todos():
    return todos

@app.get("/todos/{todo_id}")
def get_todo(todo_id: int):
    for todo in todos:
        if todo.id == todo_id:
            return todo
    return {"error": "Todo not found..."}

@app.put("/todos/{todo_id}")
def update_todo(todo_id: int, updated_todo: Todo):
    for index, todo in enumerate(todos):
        if todo_id == todo.id:
            todos[index] = updated_todo
            return {"message": "Todo Updated", "data": updated_todo}
    return {"error": "todo not found..."}

@app.delete("/todos/{todo_id}")
def delete_todo(todo_id: int):
    for index, todo in enumerate(todos):
        if todo_id == todo.id:
            todos.pop(index)
            return {"message": "todo deleted"}
    return {"error": "todo not found..."}
```

## Key concepts

**1. CRUD → HTTP methods mapping**
This is the core idea of the whole lecture:

| Operation | HTTP Method | Route            | Purpose                    |
|-----------|-------------|-------------------|-----------------------------|
| Create    | `POST`      | `/todos`          | Add a new todo              |
| Read (all)| `GET`       | `/todos`          | List every todo             |
| Read (one)| `GET`       | `/todos/{todo_id}`| Get one specific todo       |
| Update    | `PUT`       | `/todos/{todo_id}`| Replace an existing todo    |
| Delete    | `DELETE`    | `/todos/{todo_id}`| Remove a todo               |

Notice `GET /todos` and `POST /todos` share the same path but differ by method — and same for the `{todo_id}` routes. FastAPI routes by **method + path** together, not path alone.

**2. In-memory storage**
```python
todos = []
```
A plain Python list acting as a stand-in "database." This is great for learning but has a real limitation: **all data disappears when the server restarts** (that's why `--reload` will wipe your todos every time you save a code change). Later lectures will likely replace this with a real database.

**3. Combining path parameters + request body**
```python
@app.put("/todos/{todo_id}")
def update_todo(todo_id: int, updated_todo: Todo):
```
This is new: the function takes **two kinds of input at once**:
- `todo_id` → comes from the URL path (`{todo_id}`)
- `updated_todo` → comes from the JSON request body (because it's typed as `Todo`, a Pydantic model)

FastAPI figures out where each argument comes from automatically, based on whether its name is in the path and whether its type is a Pydantic model.

**4. Finding items with `enumerate()`**
```python
for index, todo in enumerate(todos):
    if todo_id == todo.id:
        todos[index] = updated_todo
```
`enumerate()` gives you both the **index** and the **item** while looping. This is needed here because to *update* or *delete* an item in a list, you need to know its position — not just the item itself.

**5. Handling the "not found" case**
Every lookup-by-id route loops through `todos` and falls through to a `return {"error": "..."}` if nothing matches. This works, but note: it currently returns a normal `200 OK` response with an error message inside it, rather than a proper `404 Not Found` HTTP status. (A common next step is learning `HTTPException` to send real error status codes — worth asking about if a future lecture doesn't cover it.)

**6. Why `id` is part of the `Todo` model**
Since there's no database auto-generating IDs, the client is expected to send an `id` themselves when creating a todo. This is simple for learning, but in real apps IDs are usually generated server-side (e.g., auto-incrementing or UUIDs) to avoid duplicates/conflicts.

## Quick recap
- CRUD maps cleanly to HTTP methods: POST (create), GET (read), PUT (update), DELETE (delete)
- Same path can have multiple routes as long as the HTTP method differs
- A route can mix a path parameter and a Pydantic-model body parameter in one function
- `enumerate()` is useful when you need an item's index to modify/remove it in a list
- In-memory lists are fine for learning CRUD logic, but not persistent — a real project will need a database
