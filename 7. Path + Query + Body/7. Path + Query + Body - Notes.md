# 7. Path + Query + Body

## What this code does
Shows how **all three parameter types** — path, query, and body — can be used together in a single route.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

users = []

class User(BaseModel):
    name: str
    age: int

@app.get("/users")
def get_users():
    return users

@app.post("/users")
def create_user(user: User):
    users.append(user)
    return {"message": "User Added", "data": user}

@app.put("/users/{user_id}")
def updated_user(user_id: int, user: User, notify: bool = False):
    if user_id < len(users):
        users[user_id] = user
        return {
            "message": "User Updated",
            "notify": notify,
            "data": user
        }
    return {"error": "User not found"}
```

## Key concepts

**1. Three parameter types, one function**
```python
def updated_user(user_id: int, user: User, notify: bool = False):
```
FastAPI decides where each argument comes from, purely based on its name and type:

| Argument   | Type          | Source              | Why                                                  |
|------------|---------------|----------------------|-------------------------------------------------------|
| `user_id`  | `int`         | **Path** parameter   | Its name matches `{user_id}` in the route             |
| `user`     | `User` (model)| **Body** (JSON)      | Its type is a Pydantic model, not a primitive type     |
| `notify`   | `bool = False`| **Query** parameter  | Not in the path, not a Pydantic model, has a default  |

So a full request would look like:
```
PUT /users/1?notify=true
Body: {"name": "Vaidik", "age": 23}
```

**2. This is the general rule to remember**
- Name appears in `{}` in the route → **path parameter**
- Type is a Pydantic `BaseModel` → **request body**
- Anything else (str, int, bool, etc. not in the path) → **query parameter**

You've now essentially seen every parameter source FastAPI supports, and this lecture is really about combining them, not introducing something brand new.

**3. Using `user_id` as a list index (a shortcut, not best practice)**
```python
if user_id < len(users):
    users[user_id] = user
```
Here, `user_id` is being used directly as the **index** into the `users` list, rather than matching an `id` field like in the Todo app (lecture 6). This works only because there's no real `id` field on `User` here — it's a simplification for this example, but it's fragile: if users are deleted or reordered, `user_id` no longer reliably points to the "right" user. The Todo app's approach (matching an explicit `id` field) is the more realistic pattern.

**4. `notify: bool` as an optional flag**
```python
notify: bool = False
```
A common real-world pattern: an optional query flag that changes behavior slightly (e.g., "should this update trigger a notification?") without being core data. It defaults to `False` so most requests can just omit it.

## Quick recap
- A single route can accept path, query, and body parameters simultaneously
- FastAPI determines the source automatically: `{}` in path → path param, Pydantic model → body, everything else → query param
- Optional flags (like `notify: bool = False`) are a common use for query parameters
- Watch out: using a path parameter directly as a list index (as done here) is a simplification, not a robust real-world pattern
