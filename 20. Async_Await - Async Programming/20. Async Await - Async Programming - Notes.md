# 20. Async / Await - Async Programming

## What this code does
Steps back from database CRUD to cover a foundational concept: **asynchronous** route functions using `async def` and `await`, and why they matter for FastAPI's performance.

```python
import time
import asyncio
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def home():
    await asyncio.sleep(3)
    return {"message": "Async API"}
```

## Key concepts

**1. The two commented functions are the whole lesson, side by side**
```python
def task():
    time.sleep(3)   # synchronous / blocking
    return "Done"

async def task():
    await asyncio.sleep(3)   # asynchronous / non-blocking
    return "Done"
```
Both "wait 3 seconds," but they behave completely differently under the hood — that difference is the entire point of this lecture.

**2. `time.sleep(3)` — blocking**
This **freezes the entire program** for 3 seconds. If this were inside a FastAPI route, the whole server (or at least that worker) would be stuck doing nothing but waiting — unable to handle *any other incoming request* during those 3 seconds.

**3. `await asyncio.sleep(3)` — non-blocking**
This pauses **only this specific function**, and hands control back to the event loop, which is free to go handle other requests in the meantime. Once the 3 seconds are up, execution resumes right where it left off. The server as a whole stays responsive to other users.

**4. `async def` — declaring an asynchronous function**
```python
async def home():
```
Marking a function `async def` makes it a **coroutine** — a function that *can* be paused and resumed, instead of running start-to-finish uninterrupted. You can only use `await` inside an `async def` function.

**5. `await` — pausing without blocking**
```python
await asyncio.sleep(3)
```
`await` says: "pause here, let other work happen, and resume me once this finishes." It only works with "awaitable" things — like `asyncio.sleep()`, or async database/HTTP calls in real projects (e.g. async DB drivers, `httpx` async requests).

**6. Why this matters for FastAPI specifically**
FastAPI is built on an async foundation (Starlette + `asyncio`). When you write routes as `async def` and use `await` for slow operations (network calls, sleeps, async DB queries), a single server process can handle **many requests concurrently** — instead of processing them strictly one at a time.

**7. When `def` (not `async def`) is still fine**
Not every route needs to be `async def`. If a route does purely CPU-bound or synchronous work (like the `sqlite3`/SQLAlchemy examples in earlier lectures, which weren't `async`), FastAPI actually runs plain `def` routes in a separate thread pool automatically — so they don't block the main event loop either. `async def` becomes essential specifically when you're doing I/O that has a proper async version to `await` (like `asyncio.sleep`, async HTTP clients, or async database drivers).

## Quick recap
- `time.sleep()` → blocks the entire program; nothing else can run during it
- `asyncio.sleep()` + `await` → pauses just this function, letting the server handle other requests meanwhile
- `async def` → declares a function as a coroutine, allowing use of `await` inside it
- `await` → pause-and-resume, used specifically with async-compatible operations
- This is *why* FastAPI can handle many concurrent requests efficiently — as long as slow operations are properly `await`ed instead of blocking
