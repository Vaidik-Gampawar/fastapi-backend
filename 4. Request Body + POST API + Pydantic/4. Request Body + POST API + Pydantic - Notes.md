# 4. Request Body + POST API + Pydantic

## What this code does
Introduces **POST requests** and how to accept structured JSON data (a "request body") using **Pydantic** models instead of simple query/path params.

```python
from fastapi import FastAPI
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int

app = FastAPI()

@app.post("/create-user")
def create_user(data: User):
    return {
        "message": "User Created",
        "data": data
    }
```

## Key concepts

**1. Why POST instead of GET**
- `GET` (lectures 1–3) → for *retrieving* data, no body, data passed via path/query params
- `POST` (this lecture) → for *sending/creating* data, data passed in the **request body** as JSON

This is a REST convention: use the HTTP method that matches the intent (fetch vs create).

**2. Pydantic `BaseModel`**
```python
class User(BaseModel):
    name: str
    age: int
```
This defines the **shape** of the expected JSON data — like a schema/blueprint. Each attribute + type hint becomes a required field.

Example of a matching request body:
```json
{
  "name": "Vaidik",
  "age": 22
}
```

**3. Using the model as a parameter type**
```python
def create_user(data: User):
```
When a function parameter's type is a **Pydantic model** (not `str`/`int`/etc.), FastAPI knows to:
- Look for this data in the **request body**, not the URL
- Parse the incoming JSON
- Validate every field against the model
- Give you a ready-to-use Python object (`data.name`, `data.age`) instead of a raw dict

**4. Automatic validation, again**
If the request body is missing a field, or `age` is sent as `"twenty-two"` instead of a number, FastAPI rejects it with a `422` error automatically — same validation philosophy as path/query params, just applied to JSON bodies now.

**5. How to test this**
Since POST needs a body, you can't just visit the URL in a browser like before. Use:
- The auto-generated docs at `/docs` (has a "Try it out" button for POST too)
- A tool like Postman, Insomnia, or `curl`:
```bash
curl -X POST http://127.0.0.1:8000/create-user \
  -H "Content-Type: application/json" \
  -d '{"name": "Vaidik", "age": 22}'
```

## Quick recap
- `@app.post(path)` → defines a route for POST requests
- `class X(BaseModel):` → defines the expected JSON structure with type-validated fields
- A parameter typed as a Pydantic model → FastAPI reads it from the **request body**, not the URL
- Invalid/missing fields → automatic `422` validation error, no manual checks needed
- POST endpoints need a body, so test them via `/docs`, Postman, or `curl` — not the browser address bar
