# 14. SQLAlchemy Setup + Models + Database Integration

## What this code does
Replaces the raw `sqlite3` module (lecture 13) with **SQLAlchemy**, an ORM (Object-Relational Mapper) that lets you define database tables as Python classes and manage connections more safely per-request.

```python
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import sessionmaker, declarative_base, Session
from fastapi import FastAPI, Depends, HTTPException

app = FastAPI()

DATABASE_URL = "sqlite:///./test.db"

engine = create_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False}
)

sessionLocal = sessionmaker(bind=engine)

Base = declarative_base()

class Todo(Base):
    __tablename__ = "todos"

    id = Column(Integer, primary_key=True, index=True)
    title = Column(String)
    completed = Column(String)

Base.metadata.create_all(bind=engine)

def get_db():
    db = sessionLocal()
    try:
        yield db
    finally:
        db.close()

@app.get("/")
def home(db: Session = Depends(get_db)):
    return {"message": "DB Connected Successfully"}
```

## Key concepts

**1. What an ORM gives you (vs raw `sqlite3` from lecture 13)**
Instead of writing raw SQL strings like `"CREATE TABLE todos (...)"`, you define a **Python class** that represents the table. SQLAlchemy translates your Python code into SQL behind the scenes — and later, querying/inserting/updating becomes Python method calls instead of SQL strings.

**2. `DATABASE_URL` and `create_engine()`**
```python
DATABASE_URL = "sqlite:///./test.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
```
- `DATABASE_URL` → tells SQLAlchemy *which* database and *how* to connect to it. The `sqlite:///./test.db` format means "SQLite, file located at `./test.db`." (If this were Postgres/MySQL instead, only this string would change — the rest of your code stays largely the same, which is one of SQLAlchemy's big advantages.)
- `engine` → the core object managing the actual connection to the database
- `connect_args={"check_same_thread": False}` → same reasoning as lecture 13's raw `sqlite3` flag — needed because FastAPI can access the database from multiple threads

**3. `sessionmaker` and `sessionLocal`**
```python
sessionLocal = sessionmaker(bind=engine)
```
This creates a **factory for database sessions** — not a session itself yet. A "session" is your actual workspace for talking to the database (querying, adding, committing). `sessionLocal()` (called later) produces a new session each time it's needed.

**4. `declarative_base()` and defining a model**
```python
Base = declarative_base()

class Todo(Base):
    __tablename__ = "todos"
    id = Column(Integer, primary_key=True, index=True)
    title = Column(String)
    completed = Column(String)
```
- `Base` → the parent class all your table models inherit from — this is what lets SQLAlchemy recognize `Todo` as a database table definition, not just a regular class
- `__tablename__` → the actual SQL table name
- `Column(...)` → defines each column and its SQL type. This class is doing the same job as the raw `CREATE TABLE` SQL string from lecture 13, just expressed as Python
- `primary_key=True` → marks `id` as the table's unique identifier (same role as `INTEGER PRIMARY KEY` before)
- `index=True` → tells the database to build a search index on this column, making lookups by `id` faster

**5. `Base.metadata.create_all(bind=engine)`**
This is the ORM equivalent of `CREATE TABLE IF NOT EXISTS` — it looks at every model that inherits from `Base` (here, just `Todo`) and creates the corresponding table(s) in the database if they don't already exist.

**6. The `get_db()` dependency — a very important pattern**
```python
def get_db():
    db = sessionLocal()
    try:
        yield db
    finally:
        db.close()
```
This is a **generator function** used as a FastAPI dependency (recall `Depends()` from lecture 11). The `yield` (instead of `return`) is key:
- Code **before** `yield` runs when the request starts → opens a fresh database session
- The `yield`ed value (`db`) is what gets injected into your route
- Code **after** `yield` (inside `finally`) runs **after the route finishes** → closes the session

This guarantees every request gets its **own, clean database session**, and that session is always properly closed afterward — even if an error occurs, thanks to `finally`.

**7. Using it in a route**
```python
def home(db: Session = Depends(get_db)):
```
`Depends(get_db)` injects a ready-to-use `db` session into the route — this is the same dependency injection pattern from lecture 11, just now used for database access instead of authentication.

## Quick recap
- `create_engine(DATABASE_URL)` → the core connection manager to your database
- `sessionmaker(bind=engine)` → a factory that produces new database sessions on demand
- `declarative_base()` + a class with `Column(...)` fields → defines a table as a Python class (a "model")
- `Base.metadata.create_all(bind=engine)` → creates all defined tables if they don't exist yet
- `get_db()` using `yield` + `try/finally` → the standard FastAPI pattern for giving each request its own DB session and safely closing it afterward
- `Depends(get_db)` in a route → injects a working database session, ready to query
